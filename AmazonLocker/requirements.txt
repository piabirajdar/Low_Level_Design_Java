#    b. System returns locker number and unique access code or error if no lockers available
# 2. Upon successfull deposit an access token is generated and returned
#    a. One access token per package
# 3. User retrieves package by providing locker number and access code
#    a. System verifies access code and returns the locker number
#    b. If valid, locker is opened and package is retrieved
#    c. If invalid, error message is returned
# 4. Access tokens expire after 7 days if package is not retrieved
#    a. System sends notification to user before expiration
#    b. expire packages automatically free up space
# 5. Invalid access tokens are rejected with error message
#    a. wrong code, already used or expired -- user gets specific feedback

# Entities:
# Locker ---The orchestrator. Owns all compartments, the AccessToken lookup map, and an occupancy set tracking which compartments are in use. Handles deposit and pickup operations.
# Comparements --- A physical locker slot. Has an ID and a size. No knowledge of access tokens — it's just a dumb container.
# Access Token. --- Represents a bearer token for compartment access. Holds the code, expiration timestamp, and a reference to the compartment it unlocks. Enforces expiry when validating.
