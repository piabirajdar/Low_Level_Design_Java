Requirements:
1. Track inventory for products across multiple warehouses
2. Add stock to a specific warehouse (receiving shipments)
3. Remove stock from a specific warehouse (fulfilling orders)
4. Check availability: given a product and quantity, return which warehouses can fulfill it
5. Transfer stock between warehouses
6. Low-stock alerts
7. Reject operations that would result in negative inventory
8. System must be thread-safe to handle concurrent operations

Out of Scope:
- Product catalog management (products exist externally)
- Order processing / payment / serviceability
- Persistence


Entities:
1. warehouse - Represents a single storage location. Holds a map of productId → quantity. Enforces the "no negative stock" invariant. Owns its alert configurations and fires alerts when stock changes trigger thresholds. Does not know about other warehouses.
2. InventoryManager - Manages multiple warehouses. Routes requests to the appropriate warehouse(s). Handles transfers between warehouses. Provides the API for adding/removing stock, checking availability, and configuring alerts.
3. AlertConfig - A value object grouping the threshold and the listener to notify when stock drops below that threshold.
4. AlertListener - An interface defining a method to be called when a low-stock alert is triggered. Implementations could send emails, call webhooks, etc.
